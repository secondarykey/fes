# Humming Bird 2026 秋 会場マップ 作業メモ

2026-10-10 に作成。2025 春のマップから 2026 秋に切り替えたときに、何のデータをどう使ったかの記録。
手順そのものは [maps-update](../../../docs/skills/maps-update/SKILL.md) を参照。

|---|---|---|---|

### 対応表（shops.tsv）

- **店名・説明（name / desc）**: チラシの店舗一覧を画像から目で読んで書き起こした（105 枠 + Harbor Art Village の 8 店）。
- **申込との対応（app）**: 店名を正規化して自動照合し、目で確認した。申込があるのは 91 店。表記ゆれ（`でぶ屋`↔`うまいもん でぶ屋` など）は同じ店と判断している。
- **申込が無い店（14 件）**: 1, 5, 10, 33, 40, 69, 89, 90, 97, 100, 101, 103, 104, 105。説明はチラシのみで、写真・リンクなし。
- **説明文（text）**: 基本は申込の販売メニュー。主催者向けの回答（「なし」「関係ない」「物販希望」など）は `-`（チラシの説明）にし、一部だけ主催者向けのもの（47, 49）は削った文を書いた。
- **リンク（links）**: 申込の URL 欄から自動で作る。`@xxx` は Instagram とみなした。判断できなかった 27, 39, 68, 84 は主催者の確認で Instagram に決めた。
- **タップ範囲（rects）**: マップ画像から凡例の色で四角を自動検出し、番号を目で割り当てた。斜めの 100, 101 と、文字の入った札（1 の BAR & BEER / BEER）は範囲を絞って検出した。ステージ・本部・トイレ・ゲート・海岸は手で範囲を決めた。
- **施設（group = facility）**: ステージ A〜D の説明はチラシの記載。隠れハッち（SECRET）は遊具の六角形の中心（「遊」と「具」の間）に 10×10px で置いた（24 日限定）。

### 店舗画像

1. `tools/images extract` で ZIP から取り出し、店舗番号ごとに分けた。ZIP には Drive の ID が無いので、ZIP の更新時刻 +16 時間（自動推定）と申込の回答時刻で対応づけた。全回答で写真の枚数が一致した。
2. 向きを補正した。webp 化では EXIF の向きが反映されないため。
   - JPEG: `D:\Go\Tools\webp\rotate` で `{n}_rotate.jpg` を作った（179 枚）。
   - HEIC: `tools/heicrot` で `{n}_rotate.png` を作った（6 枚）。22 の 2 枚は EXIF の向きが実際と合わなかったので補正していない。
3. `D:\Go\Tools\webp`（webp.go）で webp 化した。横長・正方形は横幅 1000、縦長の 153 枚は `-h 1000` で高さ 1000 にした（最初は全部横幅 1000 で 32MB だったのを 24MB にした。大きい方は `work/rejected/tall`）。元が webp の 5 枚は `.webp.png` の名前で縮小した。
4. `tools/images install` で `public/images` に置いた。
5. 78 Re:彩cle と 79 まかろんは申込が 1 件で写真 2 枚を共有していたので、内容を見て古着の写真を 78、食品サンプルの写真を 79 に分けた（外した写真は `work/rejected`）。

### GPS 基準点

1. 「広野座標」の 36 点を、マップ上の外周の線に、歩いた距離の比率で並べた。主催者の説明: 店舗の外側（裏側）を歩いた、ステージは後ろ側、1〜3 はゲート付近。
   - 上辺（`tops`）: 3〜18。ゲートの赤線上端 → ステージの後ろ → 店の列の裏 → 東端。
     折れ線 `(1458,195) (1400,178) (1340,170) (1300,148) (1225,138) (1150,148) (1110,166) (1010,168) (760,162) (495,157) (430,150) (385,150) (320,170)`
   - 下辺（`bottoms`）: 21〜36（27, 28 を除く）。東の下の角（キッチンカーの外）→ 店の列の裏 → 西の赤線下端。
     折れ線 `(330,465) (520,465) (650,470) (790,470) (930,468) (1100,458) (1330,455) (1440,445) (1478,425)`
   - 使っていない点: 1, 2（ゲート付近）、19, 20（東の縁）、27, 28（BAND STAGE 付近の出入り）。
2. 基準点が外周に沿って上下するため、`createBetweenLongitudePoint` で y も補間するようにした。
3. 会場の内側の精度は未確認（現地で数か所に立って確認するのが確実）。

## 画面・動作の変更（バージョン 0.2.0）

2025 春（0.1.0）からの変更。コードはブランチ `claude/maps-data-automation-bd3d53`（`features` にマージ済み）。

| 対象 | 変更 | 主なファイル |
|---|---|---|
| 現在地 | 鳥を現在地の中心に描く。画像の読み込み前に届いた最初の位置も反映する。位置が取れない・マップ外のときは仮の位置を出さず鳥を消す。GPS を高精度（`enableHighAccuracy`）にする。基準点の外は延長して計算し、画像の外だけを除外する | `Map.jsx`、`MapPoint.jsx`、`App.jsx` |
| 店舗データ | 直書きをやめ、`src/data/shops.json` を読む | `MapPoint.jsx` |
| お知らせ | 黒い固定サイズの箱をカード型にした（スマホ幅対応、外側を押しても閉じる）。「サイトに戻る」（`/`）を追加 | `App.jsx`、`App.css` |
| 店舗パネル | カード型にした。区分を凡例の色で表示、番号のバッジ、リンクはボタン（本文への HTML 差し込みは廃止）、✕ と「マップに戻る」で閉じる | `App.jsx`、`App.css` |
| 写真 | 複数枚を左右のボタンで切り替えるスライドショー（点で何枚目かを表示）。縦長の写真は全体を収め、余白に同じ写真をぼかして敷く | `App.jsx`、`App.css` |
| マップの操作 | スクロールバーを消した。PC はマウスのドラッグ（5px 以上動かしたらクリック扱いにしない）とホイールで横に動く。タッチはブラウザ標準 | `Map.jsx`、`App.css` |
| タイトル | Humming Bird 2026 秋 / 2026 Fall | `App.jsx`、`index.html` |

反映は `app/` で `go generate ./...`（manage と maps の `npm run deploy`）→ `gcloud app deploy`（→ [fes-deploy](../../../docs/skills/fes-deploy/SKILL.md)）。店舗画像は Git に入っていないので、デプロイする環境の `maps/public/images/` にあること（控えは `maps/work/public-images`）。

## 引き継ぎ（2026-10-10 時点）

本番での動作確認は別のセッションで行う予定。確認して問題があれば、ここから着手する。

### 実環境で確かめること

- [ ] **現在地（スマホ・https）**: 何か所かに立って鳥の位置を見る（SEASIDE STAGE の前、Harbor Art Village、ゲート、上の店の列の裏など）。内側の精度は未確認。ずれる場合は、上の「GPS 基準点」の折れ線（`tops` / `bottoms`）を見直すか、現地で基準点を記録する仕組み（[maps-automation](../../../docs/plans/maps-automation.md) の改善案 3）を検討する
- [ ] 位置情報を許可しない・会場の外にいるときは、鳥が出ないこと（仕様）
- [ ] **タッチ操作**: スクロールバーを消した後も、指での横スクロールとタップが今までどおりか。店の四角は小さい（画像上 20px 前後）ので、狙った店が開くか
- [ ] 店舗パネル（スマホ幅で 80%）・スライドショー・縦長の写真・リンクのボタン（Instagram が開くか）
- [ ] お知らせの「サイトに戻る」でトップに戻るか（本番の `/`）
- [ ] 隠れハッち（遊具の文字の間、10×10px）が実機で押せるか（押しにくすぎないか）
- [ ] 写真の表示が遅くないか（下の Cache-Control の件）

### まだやっていないこと（候補）

- [ ] `/maps/` に `Cache-Control` を付ける。embed したファイルには更新日時が無く、`Last-Modified` も `Cache-Control` も付かないので、同じ写真を開くたびに送り直している可能性がある（`app/handler/internal/maps.go`）
- [ ] お知らせの文言「次回の開催から導入されるかもしれない」はプロトタイプ時代のもの。今回の開催向けに変えるか。「お問い合わせ」をサイトのページへのリンクにするか
- [ ] お知らせを閉じた後、サイトに戻る手段が無い（ブラウザの戻るのみ）。マップの画面にも小さな戻るボタンを置くか
- [ ] 写真の無い店・施設は大きな「NO IMAGE」になる。区分の色の帯にハッちのアイコン、などに変えるか
- [ ] 店舗画像を GCS に置く（開催中の写真の差し替えが多いとき。[maps-automation](../../../docs/plans/maps-automation.md)）

### データの確認待ち（主催者）

- [ ] 店名の表記ゆれの照合結果（19 件）と、説明文を判断で変えたもの（8 件）の確認
- [ ] 7 でぶ屋の説明: チラシ（肉巻きおにぎり、タイ風唐揚げ、かき氷等）と申込（フライドポテト、唐揚げ、焼きそば…）の内容が違う。今は申込を表示
- [ ] 29 KITCHEN RACKLU の説明: 今はチラシ。最初の申込のメニュー欄の方が詳しい
- [ ] 申込が無い 14 店の書き起こしの誤読確認
- [ ] 10 極燻は 9 淡路島バーガーと同じ出店者かもしれない（申込メニューに「串焼き、燻製」）
- [ ] 写真の公開: 申込フォームでは「選考資料」として集めている。人が写っている写真もある

データを直すときは `shops.tsv` を編集して `tools/shops` で `shops.json` を作り直す（→ [maps-update](../../../docs/skills/maps-update/SKILL.md)）。

### リポジトリの後始末（履歴の書き換えの後）

2026-10-10 に、全履歴から `app/_cmd/archive` の zip とアーカイブのページ、`manage-v2`、`app/handler/internal/statik`、マップのビルド成果物を消し（約 135MB → 40MB）、GitHub の `main` と `features` を強制プッシュで置き換えた。

- [ ] `main` の保護（強制プッシュの禁止）を元に戻す（強制プッシュのために外した）
- [ ] dependabot のブランチ 3 本（opentelemetry、grpc、postcss）は古い履歴の上にある。PR を閉じて作り直してもらう（`@dependabot recreate`）。残っている限り、GitHub に古いデータが残る
- [ ] 他の PC や clone は clone し直すか、新しい履歴にリセットする。古い履歴からプッシュすると消したデータが戻る
- [ ] 別のワークツリー（`manage-deploy-method-…`、`maps-security-alerts-…`）は古い履歴のコミットを指したまま。不要なら片付ける
- [ ] 2025 春の店舗画像（`maps/public/images` の旧ファイル、履歴に約 37MB）は、`main` が新しいマップになって使わなくなった後なら、同じ方法で履歴から消せる
- [ ] `maps/work/` の片付け（ZIP から取り出した原本など。Git 管理外、約 2.2GB）
