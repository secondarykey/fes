# 会場マップのデータ作成の半自動化

2026-10-10 時点の整理。2026 秋の作業記録は [maps/data/2026-Fall/README.md](../../maps/data/2026-Fall/README.md)、手順は [maps-update](../skills/maps-update/SKILL.md) を参照。

## 方針

- 画像以外のデータ（店舗・説明・リンク・タップ範囲・GPS 基準点）は**事前に作ってビルドに含める**。会場で動的に取りに行かない。
- 店舗の位置は「マップ画像上の番号の位置」で決める。店ごとの GPS は使わない（マップはデフォルメされているので、店の実際の位置とは合わない）。
- GPS が意味を持つのは来場者の現在地の表示だけ。そのための基準点（GPS と地図上の位置の対応）は、現地で測った座標から作る。
- 1 つの対応表（`data/<開催>/shops.tsv`）を正にして、JSON はツールで生成する。人の判断は対応表に書き残す。
- 申込の CSV や写真の原本は個人情報を含むので、リポジトリに入れない（写真の作業場所 `maps/work/` は Git 管理外）。
- マップはアーカイブせず、開催ごとに作り直す。そのため店舗画像（`public/images/{店舗番号}/`）も Git に入れない。開催ごとに数十 MB ずつリポジトリが大きくなるのを避けるため。元の写真（Drive の ZIP）とツールがあれば作り直せる。
- 店舗画像は今は手元でビルドしてバイナリに埋め込んで配信する。GCS に移すのは、開催中の写真の差し替えが多いと分かったとき、または店主が写真を上げる仕組み（[event-master.md](event-master.md)）に着手するとき。それまでは `/maps/` に `Cache-Control` を付けて、同じ画像の再送を減らす。

## 現状（2026 秋の時点）

| 工程 | 状態 | 道具 | 残っている手作業 |
|---|---|---|---|
| 申込 → 店舗データ（JSON） | ほぼ自動 | `tools/shops` | 対応表の手直し |
| 写真 → 店舗画像 | 半自動 | `tools/images`、`tools/heicrot`、`D:\Go\Tools\webp`（webp・rotate） | 向きの補正と webp 化が別ツールで手順が多い |
| 店名・説明の書き起こし | 手作業 | なし | チラシの画像を目で読む。誤読のおそれ |
| 申込との照合・説明文の選別 | 半自動 | `tools/shops`（照合結果の報告） | 表記ゆれ・主催者向けの回答を人が判断 |
| タップ範囲 | 半自動・**再現できない** | 凡例の色で検出（一時スクリプト。リポジトリに無い） | 番号の割り当てを目で行う |
| GPS 基準点 | 半自動・**再現できない** | 外周の歩行記録を折れ線に当てはめ（一時スクリプト。リポジトリに無い） | 外周の折れ線を手で決める。内側の精度は未確認 |

## 改善案（効果の大きい順）

### 1. 申込フォームを変える（コード不要）

- 「マップに載せる紹介文」の欄を分ける。主催者向けの回答（「なし」「物販希望」など）と混ざらなくなり、説明文の選別が要らなくなる。
- Instagram のアカウント名の欄を作る（`@` 無しで入力してもらう）。リンクの推測が要らなくなる。
- 「掲載用の写真」と「マップ・サイトへの掲載可否」の欄を作る。今の写真は「選考資料」として集めているので、掲載の同意が曖昧。
- 写真は横長を推奨する（店舗パネルは横長の枠に切り抜いて表示する）。

### 2. 出店番号と申込の対応表を主催者側で持つ

番号を割り振るときに「番号・申込の店名（・カテゴリ）」の表を作っておけば、チラシからの書き起こしと店名の照合が不要になる。チラシの元データ（デザインの元ファイルや表）からテキストで受け取れるなら、それでもよい。

### 3. 現地で基準点を記録する仕組みをアプリに入れる

デバッグ表示で「今ここ」とマップをタップすると、GPS と地図上の位置の組を保存する。会場を歩きながら数十点を取れば、外周の線を推測で当てはめる必要がなく、内側の精度も上げられる。デフォルメされた地図には、点を三角形でつないで三角形ごとに変換する方式（区分的アフィン変換）の方が合うので、点が増えたら変換方式も見直す。

### 4. タップ範囲の検出をツールにする

凡例の色で四角を検出し、確認用の重ね合わせ画像を出すツールをリポジトリに入れる。番号の割り当ては、アプリのデバッグ表示でクリックして直せるようにする。マップが変わったときに取り直しが楽になる。

### 5. 写真の処理を 1 コマンドにする

向きの補正（JPEG・HEIC）、縮小、webp 化をまとめる。webp の変換ライブラリは cgo なので、`tools/heicrot` と同じく go.mod を持つ別モジュールにする。

## 将来
